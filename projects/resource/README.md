# @cccteam/resource

A framework-neutral TypeScript client for APIs generated by the Go
[`ccc/resource`](https://github.com/cccteam/ccc/tree/master/resource) package. It has
no Angular, RxJS, or ccc-lib dependency: the core is `fetch` and promises, and a UI
framework hooks its own reactivity onto two seams — a pluggable `Transport` and a
subscribable permission `Store`.

The ccc generator emits `zz_gen_api.ts` next to the other `zz_gen_*.ts` files: a
descriptor of the API (routes, scopes, keys, operations) plus the shapes only the
generator can derive — per-resource `Create` and `Patch` interfaces, key tuples, and
the `Api` type. This package interprets the descriptor at runtime, so behavior fixes
ship here without regenerating applications.

```ts
import { createApi } from './zz_gen_api';

const api = createApi({ baseUrl: '/api' });

// Global resources hang off the root.
const suppliers = await api.suppliers.list({ sort: { field: 'name' }, limit: 100 });

// Domain-scoped resources exist only on a client bound to a domain; calling one
// without a domain does not compile.
const station = api.domain('ws-alpha');
const orders = await station.workOrders.list({ capabilities: ['Update', 'Delete'] });
await station.workOrderTasks.patch([orders[0].id, 1], { done: true });
await station.scheduleWorkOrder.execute({ workOrderId: orders[0].id, assignedTeamId, dueAt });

// Several operations, one transaction.
await api.batch([station.requisitions.ops.add(values), station.requisitionLines.ops.add(line)]);
```

## What the types enforce

- A resource handle carries only the operations the server generated. A read-only
  view has `list` and `read`; a resource whose PATCH handler is suppressed has no
  `create`, `patch`, or `remove`.
- `Create` shapes exclude server-owned fields (output-only, state columns, the tenant
  key) and a server-generated key; a client-assigned key is required.
- `Patch` shapes additionally exclude immutable fields and keys.
- Keys are named tuples in route order, so a compound key is never a hand-joined
  string.
- Filters and sorts are typed against the row's fields. The server's filter grammar
  is available directly as a string when needed.

## Permissions

`api.permissions` is the session user's digest cache: one digest per scope (global,
or one per domain), loaded on demand and cached for the session.

- `handle.can(permission)` and `method.can()` answer synchronously from the cache and
  never fetch. `granted` and `conditional` both answer true: render the surface and let
  the server narrow it per row. A scope that has not been loaded answers false.
- `handle.rowCan(row, 'Update' | 'Delete')` asks the row first, the digest second: a
  capability envelope on the row (from `capabilities: [...]` on the read) decides for
  that row; without one, the scope's digest decides. `rowCan(row, 'Execute', method)`
  answers whether the named RPC method applies to the row, and
  `rowCan(row, 'Create', member)` whether the named workflow member resource may be
  created beneath it (the create-under-parent affordance — the add-button gate for a
  child list, e.g. lines under a draft requisition).
- `handle.grantedFields(permission)` is the digest's field-level enumeration — for
  `Create`, the inputs a create form is worth rendering: sorted field names whose
  dotted target is granted or conditional (a denied field is absent). Undefined means
  the digest carries no field-level entries for the permission — no field information
  (denied outright, or a keys-only resource) — so narrow only on a defined answer.
  Key fields never appear: they are structural, not grant-bearing.
- `api.permissions.loadDigest(domain?)` loads a scope; `loadDomains()` fetches the
  domains where the user holds any grant; `subscribe` notifies a UI framework.

Never poll a check endpoint per field. Enforcement stays server-side; everything here
is advisory material for what to render.

## Transports

`fetchTransport()` is the default. A framework routes requests through its own HTTP
stack by passing a `Transport`; ccc-lib ships `httpClientTransport` so Angular apps
keep their interceptors. A transport resolves for every HTTP status; the client turns
4xx and 5xx into `ApiError`, which carries the decoded body.

## Escape hatches

- `api.request(method, path, options)` issues any request under `baseUrl`.
- `api.define(descriptor)` builds a typed handle for a resource the generator did not
  describe, such as one registered manually on the server.
